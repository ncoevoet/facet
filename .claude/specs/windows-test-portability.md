1. **Relink: the TOCTOU receipt compares two different NTFS timestamps on Windows (PRODUCT BUG, `db/relink.py:148` and `:375`).**
   - probe (`probe3.py`, `probe6.py`, 400 files each): `os.fstat(fd)` and `os.stat(path)` agree on `st_dev`, `st_ino`, `st_size`, `st_mtime_ns` always. Only `st_ctime_ns` differs, and only when the file's times were set after creation (`shutil.copy2`, `utime`, `copystat`): 400/400 after `copy2`, 3/400 after a plain write. `fstat` ctime = the preserved creation time, `stat(path)` ctime = the real change time, 16 ms to >1 s later; stable on re-stat, so two timestamps behind one field, not a race. Photo libraries are copy-with-preserved-times, so this refuses legitimate relinks in production.
   - the stored `'stat'` is compared again at `db/relink.py:375` ("changed while decoding"): same defect, same fix. `:451` compares two fstat-derived receipts and is consistent.
   - key decision: drop `st_ctime_ns` on win32 (weakens the guard) vs. take both stamps from one API on Windows only. Default: POSIX keeps `os.stat(path)` EXACTLY as today (no behaviour change, no FIFO/permission risk). Only win32 uses a new `_path_stamp(path)`: `if sys.platform != 'win32': return _stat_stamp(os.stat(path))`; otherwise `fd = os.open(path, os.O_RDONLY | os.O_BINARY)`, `os.fstat(fd)`, close in `finally`. Windows has no FIFOs and `_canonical` already refuses links, so the open cannot block. ctime stays in the stamp on both platforms: nothing is weakened.
   - prototype (`patch_relink.py`, which used the open+fstat form unconditionally): `tests/test_relink.py` 12 failed -> 3 failed (the other 3 are step 3: JSON-escaped assertion, symlink privilege, open-handle replace), twice. The platform-gated form is a narrowing of that prototype and must be re-run (step verify).
